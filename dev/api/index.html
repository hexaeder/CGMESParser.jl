CGMESParser.CGMESParser — Module
CGMESParser

Reader and inspection tools for CGMES (Common Grid Model Exchange Standard) datasets.

A CIMDataset is a faithful in-memory image of a directory of CGMES profile files: objects keep the class names and property names from the XML, and the references between them are resolved in both directions so the model can be walked as a graph. On top of that sit three optional layers — cleanup transformations, the topological split into buses and branches, and a semantic layer that reads per-unit voltages and injections.

Plotting lives in a package extension; load GraphMakie together with a Makie backend to get inspect_collection and friends.

source
CGMESParser.CIMDataset — Type
CIMDataset(directory::String)

Read a whole CGMES dataset: every XML file in directory becomes a CIMFile, and the references between all of them are resolved.

This is a faithful image of what the files say. Nothing is cleaned up and nothing is interpreted — see the transformations and split_topologically for that.

CIMFile(filepath::String)

CGMESParser.CIMCollection — Type
CIMCollection

A bag of objects and extensions with no file structure attached. Subgraphs produced by split_topologically are collections, as is the result of flattening a CIMDataset with CIMCollection(dataset).

metadata is a free-form dict that the topology functions use to record things like which buses a branch connects.

source
CGMESParser.CIMObject — Type
CIMObject

A single object out of a CGMES file, such as a Terminal or an ACLineSegment. It keeps the class name and the properties verbatim as they appear in the XML; nothing is renamed or converted.

Property values are either plain values or CIMRefs pointing at other objects. obj["SomeProperty"] follows a reference and gives you the object on the other end, and obj.backrefs holds the references pointing the other way, so the graph can be walked in both directions.

Use properties rather than the properties field to also see what extensions in other profiles added.

source
CGMESParser.CIMExtension — Type
CIMExtension

Extra properties that a second profile attaches to an object defined elsewhere — the SteadyStateHypothesis profile restating an Equipment object to give it an operating point, for instance. The extension is linked to its base object, and properties merges the two.

source
CGMESParser.CIMRef — Type
CIMRef(id::String)

A reference from one object to another, by UUID. References start out unresolved and get their target filled in by resolve_references!.

References to the CIM schema itself (enum values, written as http://... URIs) stay unresolved on purpose — see is_external_ref.

source
CGMESParser.CIMBackref — Type
CIMBackref

The reverse side of a reference: recorded on the target object so you can ask what points at it. source is the object holding the reference and prop the property it lives in.

source
CGMESParser.resolve_references! — Function
resolve_references!(collection; warn=true)

Point every reference in collection at its target and record the matching backreference, so the objects can be walked in both directions.

Existing links are cleared first, which is what makes this safe to re-run after objects have been added or deleted. References that cannot be resolved are marked as such rather than being an error.

source
CGMESParser.merge_collection — Function
merge_collection(c1, c2; warn=true, metadatakey=:merger_of)

Combine two collections into a new one and resolve the references across the seam. Warns about objects and metadata the two disagree on. The result remembers its parts under metadatakey.

Topology

CGMESParser.split_topologically — Function
split_topologically(collection; verbose=false, warn=false) -> (buses, branches)

Split a dataset into the electrical graph it describes: one subgraph per bus and one per branch between two buses. Both are returned as CIMCollections holding the objects that belong to them, so anything you can do to a dataset you can also do to a single bus.

Switching detail is collapsed on the way — closed breakers merge the nodes they join, chains of branch elements become a single branch. Each branch subgraph records the names of the buses it connects in its metadata under :src_name and :dst_name, and each bus records its index under :busidx; a branch built from several elements keeps them under :branches.

Errors on equipment classes it cannot classify, which is usually how you find out a dataset contains something not yet supported.

source
CGMESParser.reduce_complexity — Function
reduce_complexity(collection, filter_classes=String[]; del_uncon=true)

Drop the classes that carry no electrical meaning — diagram layout, geographical position, operational limits, base voltages — and then anything left unconnected. Mostly useful to get a picture small enough to actually look at.

Pass extra class names in filter_classes to remove more.

source
CGMESParser.delete_unconnected — Function
delete_unconnected(collection, keep=collection("TopologicalNode"); warn=true)

Remove objects that are no longer reachable from keep, following references in either direction. Filtering a collection tends to leave such orphans behind.

to_digraph(collection) -> (nodes, graph)

Semantics

CGMESParser.SBASE — Constant
SBASE[]

System base power in MVA used to convert the MW/MVAr values in the CGMES files to per-unit. CGMES itself carries no system base, so this is a convention of this package — set it before reading powers if your dataset assumes a different one.

CGMESParser.in_service — Function
in_service(inj)

Whether a piece of equipment (or the terminal it hangs on) is switched in. Both the Equipment profile and an SvStatus in the StateVariables profile can say, and this errors if the two disagree.

source
CGMESParser.injector_type — Function
injector_type(o::CIMObject) -> Injector

Read what a piece of equipment does to the bus it hangs on, as one of SlackType, PVType or PQYType. Powers come out in per unit and in injector convention, so a load is negative.

Dispatches on the CIM class; generators, loads, power electronics and shunt compensators are handled. Several injectors on one bus can be reduced with combine.

source
CGMESParser.Injector — Type
Injector

What a piece of equipment does to the bus it hangs on, in powerflow terms: SlackType, PVType or PQYType. Several injectors on the same bus reduce to one with combine, which is where the usual precedence applies — a slack absorbs everything, a PV bus keeps its voltage and picks up the extra power.

source
CGMESParser.SlackType — Type
SlackType(V, objs)

A bus that holds both voltage magnitude and angle. V is NaN when the node is only the angle reference and nothing fixes its magnitude.

source
CGMESParser.PVType — Type
PVType(P, V, objs)

A bus holding active power and voltage magnitude, in per unit.

source
CGMESParser.PQYType — Type
PQYType(P, Q, G, B, objs)

A bus with a fixed power injection plus a shunt admittance, all in per unit. Plain loads and generators leave G and B at zero; a pure shunt compensator leaves P and Q at zero.

source
CGMESParser.classify_branch_subgraph — Function
classify_branch_subgraph(c) -> AbstractEdgeSubgraph or nothing

What kind of branch a two-bus subgraph describes: an ACLineSegment, a PowerTransformer, a Breaker, or a MultiBranchSubgraph when several elements sit in series. Returns nothing for anything else.

Transformations

CGMESParser.filter_loopback_breakers — Function
filter_loopback_breakers(data) -> CIMCollection

Remove breakers and switches whose two terminals sit on the same topological node. They carry no current and only get in the way of the topological split.

Warns when such a breaker was marked as retained, or when the powerflow stored on its two terminals does not cancel out — either is a sign the export is not quite consistent.

source
CGMESParser.merge_tpn_on_breakers — Function
merge_tpn_on_breakers(data) -> CIMCollection

Merge topological nodes that share a name and are joined by a closed breaker, collapsing them into one bus. Exports that model busbar detail tend to hand out one node per busbar section, all carrying the same name.

See rename_dangling_tpn for the other way of dealing with duplicate node names.

source
CGMESParser.reattach_regulating_control — Function
reattach_regulating_control(data) -> CIMCollection

Point each RegulatingControl at the terminal of the equipment it actually regulates. Some exports attach it to a different terminal on the same node, which is harmless for the powerflow but confusing to read.

source
CGMESParser.rename_dangling_tpn — Function
rename_dangling_tpn(data) -> CIMCollection

Give unique names to topological nodes that share a name with another node. Only nodes with a single neighbour are renamed, by prefixing that neighbour's name.

Duplicate node names can also be a sign that a node was split across a breaker, in which case merge_tpn_on_breakers is the remedy rather than this one.

Comparing

CGMESParser.CIMCollectionComparison — Type
CIMCollectionComparison(A::CIMCollection, B::CIMCollection)

Match up the objects of two collections, so that two exports of the same grid can be compared. Objects are matched on their class, properties and what they reference — not on UUID, which differs between exports.

The result holds the matching in both directions. Objects that are genuinely identical to one another (duplicate limits, position points) can be matched ambiguously; that is warned about but not an error.

CGMESParser.inspect_collection — Function
inspect_collection(collection; filter_out=String[], size=(2000,1500), hl1=[], hl2=[],
                   seed=1, edge_labels=true, node_labels=:long)

Plot every object in collection as a node and every resolved reference as an edge, with nodes colored by the profile they came from. filter_out drops classes whose name contains any of the given strings, which is how you get a readable picture out of a full dataset.

Requires GraphMakie and a Makie backend to be loaded.
